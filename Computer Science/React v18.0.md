[This article](https://react.dev/blog/2022/03/29/react-v18) presents the new changes in React 18, including:
- A new and improved **Concurrent React**, including asynchronous rendering (rendering happens on a separate thread, allowing the main thread to focus on user interaction), reusable state (in a minor update, they will introduce the `<Offscreen>` component, allowing the developer to explicitly control what happens when a user isn't focused on the React App), better [[React Suspense]] integration, and eventually, better Server Components.
- Automatic Batching allows for screen updates to be grouped together, maximizing the efficiency of each visual update. When you have a timeout that results in several state changes, React used to update the visuals after each state change. With automatic batching, the visual update will be flagged at the first state change, then accomplished once the rest of the timeout code is finished. See [here](https://github.com/reactwg/react-18/discussions/21) for more information.
- Transitions change how quickly different aspects of a user control get updated. Think of a search bar - when a user types, the screen should be immediately affected with the characters typed, but the suggestion list is low priority/time-consuming, and the list should only really be affected when typing is paused. Developers can wrap the list update in `startTransition(()=>{})` to allow React to handle more urgent processes before the list.
- Suspense changes include server-side-rendering Suspense support, as well as proper transition support. See [here](https://github.com/reactjs/rfcs/blob/main/text/0213-suspense-in-react-18.md) for more information.
- The React DOM Client has been updated with new `createRoot` and `hydrateRoot` (update) methods which accept `onRecoverableError` to allow for better rendering error management.
- The React DOM Server now has `renderToPipeableStream` for streaming in Node environments, as well as `renderToReadableStream` for daemons on the edge. The `renderToString` method that used to be used for both of these is still supported, but discouraged (i.e. this render method is still supported for now, but they plan to deprecate it when most developers have stopped using it.)
- `StrictMode`, a great developer mode with extra logging, has been modified to allow developers to check their components for correct `<Offscreen>` working, despite this functionality not yet being supported. This modification will now mount each component, then simulate an unmount and a remount, which should allow developers to get a handle on where issues will arrise.

## Hooks Added
- The `useId` hook has been added for easier accessibility support (think `useId` for HTML elements and their aria support), particularly during server rendering. [See more here](https://react.dev/reference/react/useId).
- The `useTransition` and `startTransition` allow the usage of transittions.
- `useDeferredValue` basically debounces renders, but also makes sure they are interruptible and do not block user input.
- `useSyncExternalStore` has been added, mainly for library writers, as new access method for external stores. Instead of trying to make everything work through `useEffect`, we can instead use this hook to treat it like a stream.
- `useInsertionEffect` will allow for CSS-in-JS concurrent render support.
